Day 5 MSE to CICFM Conversion Implementation

This document explains the Day 5 conversion contract: how the trainable MSE baseline becomes a CICFM velocity predictor while reusing the same MLP architecture, MSE reduction, and backward math.

Mode switch
explicit

Use loss_mode = mse or loss_mode = cicfm.

CICFM input
features + zt + t

Concatenate along the last dimension.

CICFM target
z1 - z0

Train the model to predict velocity, not RGB.

What Changes

Component MSE mode CICFM mode
Model input features concat(features, zt, t)
Output meaning Predicted value/RGB Predicted value-space velocity
Loss target targets target_velocity = z1 - z0
Loss formula mean((prediction - targets)^2) mean((predicted_velocity - target_velocity)^2)

What Does Not Change

  • The hidden architecture remains four linear layers total.
  • The hidden width remains 256.
  • The activation remains SiLU.
  • The output activation remains identity.
  • The MSE reduction helper is reused.
  • The linear backward and SiLU backward formulas are reused.
  • The optimizer and parameter update rule should stay unchanged.

CICFM Construction

z1 = targets
z0 ~ Uniform(0, 1)
t  ~ Uniform(0, 1), shape [B, N, 1]
zt = (1 - t) * z0 + t * z1
target_velocity = z1 - z0

cicfm_input = concat(features, zt, t)
predicted_velocity = mlp(cicfm_input)
loss = mean((predicted_velocity - target_velocity)^2)
Do not compare predicted_velocity to targets. In CICFM mode the model output means velocity.

Input Dimensions

Configuration MSE input dim CICFM input dim Output dim
D = 2, C = 3, F = 8 34 38 3
D = 2, C = 3, F = 16 66 70 3
The first linear layer changes shape between modes. A clean first implementation should construct a new model with the CICFM input dimension instead of trying to reuse an MSE model instance.

Shared Backward Math

Both modes use the same MSE output-gradient formula. The tensors passed into the formula change. 

d_output = 2 * (output - target) / count

MSE:
output = prediction
target = targets

CICFM:
output = predicted_velocity
target = target_velocity

Deterministic Smoke Test

Before random CICFM training, use deterministic assembly values: 

z0 = zeros_like(targets)
t = 0.5
z1 = targets

zt = 0.5 * targets
target_velocity = targets
cicfm_input = concat(features, 0.5 * targets, 0.5)

Required checks:

max_abs(zt - 0.5 * targets) < 1e-6
max_abs(target_velocity - targets) < 1e-6
cicfm_input.shape[2] == feature_dim + C + 1

Controlled Transition Order

  1. Train MSE mode on the deterministic synthetic overfit target.
  2. Confirm MSE loss decreases.
  3. Run deterministic CICFM batch assembly.
  4. Confirm CICFM shape and value checks pass.
  5. Run one CICFM forward pass without updating parameters.
  6. Confirm CICFM loss is finite.
  7. Run one CICFM backward pass.
  8. Confirm all CICFM gradients are finite.
  9. Only then run CICFM training updates.

Definition of Done

  1. loss_mode explicitly selects MSE or CICFM.
  2. MSE mode still uses features -> prediction -> targets.
  3. CICFM mode uses concat(features, zt, t) -> predicted_velocity.
  4. CICFM target is target_velocity = z1 - z0.
  5. The shared MSE reduction and backward formulas are reused.
  6. The deterministic CICFM smoke test is defined.
  7. CICFM training remains gated behind MSE overfit and finite-gradient checks.
