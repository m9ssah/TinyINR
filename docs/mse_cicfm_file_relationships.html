What Was Implemented

The branch implements a CPU reference for the model/loss design so the CUDA/runtime work has an executable source of truth. The reference path is intentionally direct: it favors explicit tensor shapes and hand-checkable math over performance tricks.

Contract Area CPU Reference Status Primary Files

Contract Summary

The model/loss contract has two phases. MSE is implemented first because it proves the MLP, loss, and backward math can learn direct coordinate-to-value targets. CICFM then reuses that machinery but changes the model input and target. 

MSE mode:
  features:     [B, N, D + 2 * D * F]
  prediction:   [B, N, C]
  loss_target:  targets
  loss:         mean((prediction - targets)^2)

CICFM mode:
  z0:              [B, N, C]
  z1:              targets
  t:               [B, N, 1]
  zt:              (1 - t) * z0 + t * z1
  target_velocity: z1 - z0
  cicfm_input:     concat(features, zt, t)
  loss:            mean((predicted_velocity - target_velocity)^2)
CICFM intentionally reuses the MSE reduction. The conversion is in the tensors: output meaning changes from value to velocity, and loss target changes from targets to target_velocity.

End-to-End CPU Workflow

This is the reference execution order partner runtime/CUDA code should preserve. The model input and target are selected before the shared forward/loss/backward path. 

Tensor data
  -> coordinate batch / sampled points
  -> Fourier features
  -> trainStep
       -> validate shared shapes
       -> dispatch on LossMode
       -> choose model_input
       -> choose loss_target
       -> zeroGrad
       -> mlpForward
       -> mseLossAndGradient
       -> mlpBackward
       -> finite checks
       -> sgdStep
       -> TrainStepResult

MSE Reference Path

MSE is the direct baseline and should remain the first thing to debug. In this path, the model predicts target values directly from features. 

1. coordinates: [B, N, 2]
2. targets:     [B, N, 3]
3. features = fourierEmbedding(coordinates, F)
4. trainStep(..., LossMode::MSE)
5. model_input = features
6. prediction = mlpForward(model, model_input)
7. loss_target = targets
8. loss = mean((prediction - targets)^2)
9. mlpBackward(...)
10. sgdStep(...)

For the frozen F = 8 baseline, MSE uses input dimension 34 and output dimension 3.

CICFM Reference Path

CICFM changes what the model sees and what the output means. The model receives embedded coordinates plus interpolation state and predicts velocity in value space. 

1. features: [B, N, 34]
2. targets become z1
3. sample z0: [B, N, 3]
4. sample t:  [B, N, 1]
5. zt = (1 - t) * z0 + t * z1
6. target_velocity = z1 - z0
7. cicfm_input = concat(features, zt, t)
8. trainStep(..., LossMode::CICFM)
9. predicted_velocity = mlpForward(model, cicfm_input)
10. loss = mean((predicted_velocity - target_velocity)^2)
11. mlpBackward(...)
12. sgdStep(...)

For the frozen F = 8 baseline, CICFM uses input dimension 38: 34 feature values, 3 interpolated value channels, and 1 time channel.

Partner Handoff Boundary

The current trainable baseline is CPU-only after feature embedding. CUDA currently exists for the coordinate/Fourier embedding kernel path. The CPU reference defines the expected behavior for any CUDA/runtime implementation.

Partner Area CPU Reference To Match Expected First Check
CUDA MLP forward/backward src/model/mlp.cpp Match CPU outputs and selected finite-difference gradients on a tiny model.
CUDA SiLU silu and siluBackward Match CPU values for negative, zero, and positive inputs.
CUDA MSE reduction mseLoss and mseOutputGradient Match hand-computed scalar loss and gradient.
CICFM runtime assembly makeCicfmBatch Match zt, target_velocity, and input ordering.
LossMode training wiring trainStep Use the same model input and loss target per mode.
Benchmark harness docs/final_model_loss_design.md Report separate embedding, assembly, forward, loss, backward, and step timing.
Best next CUDA/runtime check: prove the final model input contract matches the CPU reference. For F = 8, MSE input is 34 and CICFM input is 38. For F = 16, MSE input is 66 and CICFM input is 70.
