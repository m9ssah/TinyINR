TinyINR MSE/CICFM File Relationships and Workflow

An intuitive map of how the tensor, feature, model, loss, CICFM, train-step, debug, and test files work together in the current mse-cicfm branch.

Foundation
Tensor + features

Data starts as tensors, coordinates, targets, and Fourier features.

Learning Core
MLP + loss

The same four-layer SiLU MLP learns either values or velocities.

Mode Switch
trainStep

LossMode decides which input and target enter the shared training path.

Mental Model

Think of TinyINR as a pipeline with one stable training engine and two ways to prepare the tensors going into it. 

shared engine:
  model_input -> MLP -> model_output
  model_output + loss_target -> MSE loss
  MSE gradient -> MLP backward -> SGD update

MSE mode prepares:
  model_input = features
  loss_target = targets

CICFM mode prepares:
  model_input = concat(features, zt, t)
  loss_target = target_velocity
The important idea: CICFM does not need a separate loss implementation. It reuses MSE by changing the meaning of the model output and target.

Layer Map

Layer Files Role
Tensor foundation include/tensor.h, src/tensor.cpp Owns CPU float tensors, shapes, indexing, reshape, and simple math operations. Every higher-level module passes data through this class.
Coordinate data include/ops/coordinate_batch.h, src/ops/coordinate_batch.cpp Converts image-like values into normalized coordinates and target values with shapes [B, N, D] and [B, N, C].
Feature embedding include/ops/fourier_embedding.h, src/ops/fourier_embedding.cpp, src/ops/fourier_embedding_raw.cpp Converts coordinates into model features: raw coordinates + Fourier features. For D = 2 and F = 8, this produces 34 features.
MLP model include/model/mlp.h, src/model/mlp.cpp Implements the four-layer SiLU MLP, deterministic initialization, forward cache, manual backward pass, gradient clearing, and SGD update.
Shared MSE loss include/training/loss.h, src/training/loss.cpp Computes mean((output - target)^2), its output gradient, and the expected MSE/CICFM input dimensions.
CICFM assembly include/training/cicfm.h, src/training/cicfm.cpp Builds z0, z1, t, zt, target_velocity, and concat(features, zt, t).
Debug stats include/training/train_debug.h, src/training/train_debug.cpp Checks tensor, parameter, and gradient finiteness and tracks simple magnitudes.
Training dispatch include/training/train_step.h, src/training/train_step.cpp The end-to-end CPU train step. It validates dimensions, switches on LossMode, chooses model input and loss target, runs forward/loss/backward, applies SGD, and returns debug data.
CUDA embedding path src/kernels/coordinate_embedding.cu, src/kernels/coordinate_embedding.cuh, tests/test_cpu_cuda_parity.cu Covers CUDA coordinate/Fourier embedding only. The trainable MLP, loss, CICFM assembly, backward pass, and SGD step are currently CPU-only.

MSE Workflow

MSE is the direct baseline. The model sees embedded coordinates and predicts target values directly. 

1. coordinates: [B, N, 2]
2. targets:     [B, N, 3]
3. features = fourierEmbedding(coordinates, F)
4. trainStep(..., LossMode::MSE)
5. model_input = features
6. prediction = mlpForward(model, model_input)
7. loss_target = targets
8. loss = mean((prediction - targets)^2)
9. mlpBackward(...)
10. sgdStep(...)

For the frozen F = 8 baseline, MSE uses input dimension 34 and output dimension 3.

CICFM Workflow

CICFM changes the learning target from value prediction to velocity prediction. The MLP still uses the same architecture and MSE loss helper. 

1. features: [B, N, 34]
2. targets become z1
3. sample z0: [B, N, 3]
4. sample t:  [B, N, 1]
5. zt = (1 - t) * z0 + t * z1
6. target_velocity = z1 - z0
7. cicfm_input = concat(features, zt, t)
8. trainStep(..., LossMode::CICFM)
9. predicted_velocity = mlpForward(model, cicfm_input)
10. loss = mean((predicted_velocity - target_velocity)^2)
11. mlpBackward(...)
12. sgdStep(...)

For the frozen F = 8 baseline, CICFM uses input dimension 38: 34 feature values, 3 interpolated value channels, and 1 time channel.

End-to-End Dependency Flow

Tensor
  -> CoordinateBatch
  -> FourierEmbedding
  -> features
  -> trainStep
       -> LossMode::MSE uses features + targets
       -> LossMode::CICFM uses CicfmBatch input + target_velocity
       -> mlpForward
       -> mseLossAndGradient
       -> mlpBackward
       -> sgdStep
       -> TrainStepResult debug stats
  -> tests validate each boundary

CPU and CUDA Boundary

The current trainable baseline runs on CPU. CUDA is present for the coordinate/Fourier embedding kernel path, but the MLP, loss, CICFM assembly, backward pass, and SGD update are not CUDA kernels yet.

Best next CUDA step: parity-test the final model input contract concat(raw coordinates, Fourier features, zt, t) across CPU and CUDA embedding paths before implementing CUDA MLP kernels.

Quick Reading Order

  1. Start with include/training/train_step.h to see the public end-to-end API.
  2. Read src/training/train_step.cpp to see how MSE and CICFM split.
  3. Read src/training/cicfm.cpp to understand zt and target_velocity.
  4. Read src/model/mlp.cpp to understand forward/backward.
  5. Read tests/test_train_step.cpp and tests/test_full_size_baseline.cpp to see the contract enforced.
