Day 6 Loss Transition Debugging Implementation

This page describes the Day 6 implementation contract for debugging the switch from direct MSE value prediction to CICFM velocity prediction.

Primary Check
Target velocity

CICFM loss must compare predicted velocity against z1 - z0, not against raw targets.

Debug Entry
Deterministic

Start with z0 = 0 and t = 0.5 before using random CICFM batches.

Safety Gate
Finite values

Abort on the first non-finite loss, output, gradient, or updated parameter.

Debugging Order

Day 6 makes the transition incremental. The runtime should move through the following stages without skipping ahead:

  1. MSE deterministic overfit with F = 8.
  2. MSE random sampled batch with F = 8.
  3. CICFM deterministic assembly with z0 = 0 and t = 0.5.
  4. CICFM deterministic forward and backward without an optimizer step.
  5. CICFM deterministic overfit on a tiny fixed batch.
  6. CICFM random source/time batch with F = 8.
  7. CICFM random source/time batch with F = 16.
Do not tune the learning rate, architecture, Fourier feature count, or random sampler until deterministic CICFM passes finite loss and finite gradient checks.

Deterministic CICFM Probe

The deterministic probe removes sampler noise so CICFM assembly can be checked directly. 

z0 = zeros_like(targets)
z1 = targets
t = 0.5
zt = 0.5 * targets
target_velocity = targets
cicfm_input = concat(features, zt, t)

The expected invariants are:

min_t = 0.5
max_t = 0.5
mean_t = 0.5
max_abs(zt - 0.5 * targets) < 1e-6
max_abs(target_velocity - targets) < 1e-6
F = 8  => cicfm_input_dim = 38
F = 16 => cicfm_input_dim = 70

Loss Target Probe

The loss target probe catches the most dangerous conversion bug: accidentally comparing velocity output to raw targets. 

predicted_velocity = [[[0.0, 0.0, 0.0]]]
z0 = [[[0.2, 0.4, 0.6]]]
z1 = [[[0.5, 0.1, 0.9]]]
target_velocity = [[[0.3, -0.3, 0.3]]]

loss = mean((predicted_velocity - target_velocity)^2)
     = 0.09

d_predicted_velocity =
  2 * (predicted_velocity - target_velocity) / 3
  = [[[-0.2, 0.2, -0.2]]]

Finite-Value Abort Policy

Training should stop immediately on the first non-finite value. The debug output must identify the first failing tensor, index, and value. 

loss is finite
all model outputs are finite
all output gradients are finite
all parameter gradients are finite
all parameter values are finite after optimizer_step()

Shape Assertions

Shape checks are split into pre-forward and post-forward checks so the failing boundary is obvious. 

features.shape == [B, N, feature_dim]
z0.shape == [B, N, C]
z1.shape == [B, N, C]
t.shape == [B, N, 1]
zt.shape == [B, N, C]
target_velocity.shape == [B, N, C]
cicfm_input.shape == [B, N, feature_dim + C + 1]
predicted_velocity.shape == [B, N, C]
loss_target.shape == [B, N, C]
d_predicted_velocity.shape == [B, N, C]

Triage Table

Symptom Likely Cause First Check
CICFM loss equals MSE loss exactly Still using targets as the loss target Run the loss target probe
Shape mismatch in the first layer MSE model instance was reused Check input_dim and linear0.weight
NaN after optimizer step Learning rate too high or gradient explosion Check max_abs_output_gradient before the step
target_velocity changes with t Velocity formula incorrectly uses interpolation Check target_velocity = z1 - z0

CUDA Alignment

Day 6 keeps the CUDA path active by preserving the assembly boundary: CUDA may produce the Fourier-feature portion, while runtime assembly must still append raw coordinates, zt, and t in the same order as the CPU path. 

features = concat(raw_coordinates, fourier_features)
cicfm_input = concat(features, zt, t)
Day 6 is complete when deterministic CICFM is explainable, random CICFM has finite values, and every common loss-transition failure has a first diagnostic check.
