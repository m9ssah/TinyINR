TinyINR Model and Loss Design Plan

Current roadmap for the trainable TinyINR baseline: first make MSE training correct and overfittable, then convert the same model family into a CICFM velocity predictor.

Baseline
MSE INR

Predict RGB/value directly from embedded coordinates.

Architecture
4 linear layers

Width 256, SiLU hidden activations, identity output.

Conversion
CICFM

Predict value-space velocity from features, zt, and t.

Frozen Model Contract

coordinates: [B, N, D]
targets:     [B, N, C]
features:    [B, N, D + 2 * D * F]
prediction:  [B, N, C]

For the first RGB image baseline:

D = 2
C = 3
F = 8 initially, then F = 16

F = 8  -> input_dim = 34
F = 16 -> input_dim = 66

Architecture

The baseline has four linear layers total. That means three hidden layers and one output layer. 

Linear(input_dim, 256)
SiLU
Linear(256, 256)
SiLU
Linear(256, 256)
SiLU
Linear(256, C)
Output activation: identity. Do not clamp, sigmoid, or tanh the output during the first MSE baseline.

Day-by-Day Plan

Day 1Freeze Model and Loss Contract

  • Freeze tensor names and shapes.
  • Choose SiLU, width 256, and four linear layers total.
  • Define MSE first and CICFM second.
  • Document that CUDA currently returns the Fourier-feature portion.

Day 2Define MLP Forward and MSE Target

  • Flatten [B, N, input_dim] into [B * N, input_dim].
  • Apply linear, SiLU, linear, SiLU, linear, SiLU, linear.
  • Use targets as the MSE target.
  • Reduce MSE over B * N * C.
  • Use a deterministic synthetic overfit target.

Day 3Define CICFM Scaffolding

  • z1 = targets.
  • z0 ~ Uniform(0, 1).
  • t ~ Uniform(0, 1) with shape [B, N, 1].
  • zt = (1 - t) * z0 + t * z1.
  • target_velocity = z1 - z0.
  • cicfm_input = concat(features, zt, t).

Day 4Verify MSE Training Logic and Backward Math

  • Verify hand-computable MSE scalar value.
  • Verify MSE output gradient.
  • Verify SiLU derivative.
  • Verify linear backward formulas.
  • Run finite-difference checks on a tiny MLP.
  • Confirm loss decreases on a fixed synthetic batch.

Day 5Convert MSE to CICFM

  • Switch model input from features to concat(features, zt, t).
  • Switch output meaning from predicted value to predicted velocity.
  • Switch target from targets to target_velocity.
  • Keep optimizer, hidden architecture, and logging structure stable.
  • Gate CICFM training behind MSE overfit and finite-gradient checks.

Day 6Debug Loss Transition

  • Run MSE deterministic overfit and random sampled batches first.
  • Run deterministic CICFM with z0 = 0 and t = 0.5.
  • Verify CICFM compares predicted_velocity to target_velocity.
  • Log loss, time range, z statistics, velocity magnitudes, and output-gradient magnitudes.
  • Abort on the first non-finite loss, output, gradient, or updated parameter.
  • Use F = 8 before scaling random CICFM to F = 16.

Day 7Document Final Design

  • Document final MSE and CICFM tensor contracts.
  • Document overfit and gradient-check results.
  • Document known limitations and CUDA alignment work.

Current Rule

Do not convert to CICFM until MSE backward math passes gradient checks and the tiny fixed-batch MSE training run shows loss decrease.
